- ⚠️ Renamed the RTVI UI Worker Protocol's vocabulary to Pipecat's native `worker`/`job` terminology (it previously used the `pipecat-subagents` `task`/`agent` terms). Task → job-group: wire messages `ui-task` → `ui-job-group` and `ui-cancel-task` → `ui-cancel-job-group`; envelope `kind`s `task_update`/`task_completed` → `job_update`/`job_completed`; the `task_id` field → `job_id`; the paired Python models/frames (`UITaskMessage` → `UIJobGroupMessage`, `UICancelTaskMessage` → `UICancelJobGroupMessage`, `RTVIUITaskFrame` → `RTVIUIJobGroupFrame`, `RTVIUICancelTaskFrame` → `RTVIUICancelJobGroupFrame`, `UITask*Data` → `UIJob*Data`) and the internal bus carriers (`BusUITask*` → `BusUIJob*`). Agent → worker: the job-group envelope fields `agents` → `workers` and `agent_name` → `worker_name`. The matching `@pipecat-ai/client-js` / `@pipecat-ai/client-react` APIs are renamed too (`RTVIEvent.UITask` → `UIJobGroup`, `PipecatClient.cancelUITask` → `cancelUIJobGroup`, `useUITasks` → `useUIJobGroups`, `UITasksProvider` → `UIJobGroupsProvider`, the `agent_name`/`agents` envelope fields, ...). These primitives first shipped in 1.2.0 but were never documented, so no real consumers are affected.
